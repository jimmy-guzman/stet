stet opens each file read-only. It never writes to the repository. An unchanged file opens as plain source, with syntax highlighting for [each supported language](/docs/reference/languages) and no diff gutter. A changed file opens as a diff.

![A source file open in stet with syntax highlighting and no diff gutters](/screenshots/read-only.png)

## Diffs and the full-file toggle

A changed file opens as a diff. In a modified line, the words that changed have a stronger tint of the add or remove color. A one-word edit in a long line is easy to see. Press `v` to switch between the diff and the full file. If a large file is truncated, press `f` to load its full content.

## Binary and image files

A terminal cannot show an image. Instead of the raw bytes, stet shows a card with the type, the dimensions, and the size of the file. For a changed image, the card shows the old and new values side by side. Press `O` to open the file in your default app, for example an image viewer or a PDF reader.

![stet showing an image file's type, dimensions, and size instead of raw bytes](/screenshots/binary-preview.png)

## Fold code

Press `z` in the viewer to fold the block at the caret (the current position in the viewer). The folded block shows as a `▸ N lines folded` marker. Code folds by indentation, and Markdown folds by heading section.

A diff also hides the unchanged lines between changes in a gap row, `⋯ N unmodified lines`. This includes the lines after the last change. If the caret is not in a block that can fold, `z` expands the gap nearest to the caret. The gap then shows its unchanged lines, highlighted like the rest of the file, below a `hide` marker. Press `z` again to collapse it. You can also click any marker to toggle it.

A gap expands only in a diff that stet computes itself. For some files, stet uses the diff from Git instead. An example is a file with CRLF line endings on only one side. In that diff, the gap stays a plain `⋯ N unmodified lines` row.

![A diff with a function's body folded behind a "lines folded" marker, its signature still visible](/screenshots/folding.png)

<Callout>
  Folds belong to one file. They reset when you change to a different file or a
  different diff scope. To wrap long lines in the viewer instead of scrolling
  them horizontally, press `x`.
</Callout>

## Viewer history

Press `<` to go back or `>` to go forward. Both restore the caret and scroll position for that visit. When you reopen a file from the tree or the file picker, stet restores your last position in that file.

## Select and copy

Drag across text in the viewer to select it. When you release the button, stet copies the selected text. Double-click to copy a word, or triple-click to copy a line. Drag down the line numbers to copy whole lines. You can also drag across text in other parts of the interface, for example the help overlay.

From the keyboard, press `Shift+↑` or `Shift+↓` to select lines. With text selected, `Shift+↑` and `Shift+↓` move its end by a line. `Shift+←` and `Shift+→` move it by one character, except in a selection of whole lines. `esc` clears the selection.

| Key | Without a selection | With a selection |
| --- | --- | --- |
| `y` | Copies the reference `path:line` | Copies the reference `path:line-line` |
| `Y` | Copies the full contents of the file | Copies the selected text |

Paste a reference into the agent conversation to point the agent at that code. In the tree, `y` copies the file `path`.

The status bar shows `copied` when the system clipboard has the text. If stet can only send the text to your terminal, it shows `sent` instead. This occurs over SSH, for example. The terminal must support OSC 52 (the sequence that sets the clipboard through the terminal) to put that text on your clipboard.

<Callout type="warn">
  On Linux, text that you copy can be lost when you quit stet. It stays if you
  have a clipboard manager, or if your terminal supports OSC 52.
</Callout>
