## Switch scope

A scope is the pair of points that the diff compares. Press `s` to choose a scope. The scopes are in two groups. The changes group has uncommitted, staged, and unstaged changes, compared against `HEAD` by default. If you start stet with a Git ref (`stet <ref>`), the uncommitted scope compares the working tree with that ref. It then also shows the commits made after the ref. The history group has two scopes. The session scope compares the working tree with the commit that `HEAD` was on when stet started. It also shows changes that were uncommitted at that time. The last-commit scope shows the last commit. The picker also lists recent commits (`commits →`), so you can view any of them as its own diff.

![The scope picker grouping the diff scopes under changes and history](/screenshots/scope-picker.png)

To start in a scope from the command line, run `stet --staged` or `stet --unstaged`. To compare against a branch, tag, or commit, run `stet <ref>` with its Git ref.

## Switch worktrees

A Git worktree is an extra checkout in its own folder. Press `w` to change to a different worktree without leaving stet. The list puts the most recently touched worktree first, so the worktree that an agent works in is at the top. Each row shows its age (`now`, `5m`, `3h`).

Type to filter by branch or by the folder name of the worktree. Press `↑`/`↓` to move and `⏎` to switch. The filter ignores the folder path that all worktrees share. That text is the same in each row, so it always matches all rows at once.

After the switch, the tree, the diffs, and polling use the selected worktree. Below the list, stet shows the full path of the highlighted worktree.

![The worktree picker, worktrees ranked by how recently each was touched, each with its age, and the highlighted one's full path below the list](/screenshots/worktree-picker.png)

Touched means the newest of three times:

- The last edit to a file that Git still reports as changed
- The last update of the `HEAD` reflog, which is the log of where `HEAD` pointed
- The time of the `HEAD` commit

An uncommitted edit, a commit, a checkout, a rebase, and the creation of the worktree all count. Checkouts and rebases count through the reflog, which Git keeps by default. Without a `HEAD` reflog, a checkout to an older commit refreshes the age only if it leaves a changed file. A Git command that changes no file and writes no reflog entry, such as `git status`, does not count. A branch checkout writes an entry and counts, even for the branch you are already on. A commit counts, so a worktree does not drop down the list when an agent finishes its work.

The color of each age shows how recently the worktree was touched. It fades toward the background over five minutes without activity. A changed file stays marked for 30 seconds. A worktree uses a longer window, because an agent can pause for minutes and still be at work. The age shows recency, not live presence. A recent age means that work landed there recently. It does not mean that something runs there now.
