## Introduction

`stet` is a read-only companion TUI. You use it to inspect the changes that a coding agent makes. The agent runs in one terminal pane, and stet runs in the next pane. stet answers the questions that you otherwise open an editor for: which files are in the repository, what changed, and what changed most recently.

stet shows you the repository and the diff. It does not review the changes, approve them, or talk to the agent. You decide what to tell the agent next.

## Install

<Tabs items={["curl", "npm", "homebrew"]}>
  <Tab value="curl">
    A standalone binary for macOS and Linux. It needs no runtime.

    ```sh
    curl -fsSL https://stet.jimmy.codes/install | bash
    ```

  </Tab>
  <Tab value="npm">
    Works with `npm`, `bun`, `pnpm`, and `yarn`. It installs a prebuilt binary.

    ```sh
    npm i -g @jimmy.codes/stet
    ```

  </Tab>
  <Tab value="homebrew">
    ```sh
    brew install jimmy-guzman/tap/stet
    ```
  </Tab>
</Tabs>

Make sure that stet is installed:

```sh
stet --version
```

The command prints the installed release number in `X.Y.Z` form.

## Usage

Run `stet` in a Git repository. Without arguments, stet compares your uncommitted changes with the current commit (`HEAD`). To compare against a different point in history, pass a Git ref. A Git ref is a name for a commit, such as a branch, a tag, or a commit hash.

```sh
stet            # uncommitted changes vs the current commit
stet main       # compare against the main branch
stet --staged   # start in the staged scope
stet --unstaged # start in the unstaged scope
stet --no-icons # plain tree without Nerd Font file-type icons
stet --wrap     # wrap long lines in the viewer instead of scrolling them horizontally
stet --editor "nvim +{line} {file}"              # terminal editor for the e key
stet --ide    "code {repo} --goto {file}:{line}" # GUI/IDE for the o key
```

The repository tree opens beside the file viewer. Changed files open as diffs.

A new repository with no commits has no `HEAD` to compare against. In that case, stet compares against the empty tree. Staged files show as added, and untracked files show as untracked, as usual. Until the first commit, the scope (what the diff compares) shows `uncommitted vs no commits yet`. After the first commit, stet compares against `HEAD`, as in any other repository.

<Callout title="Nerd Font icons">
  The tree shows a file-type icon next to each file. These icons are [Nerd
  Font](https://www.nerdfonts.com/) glyphs. They show correctly only when your
  terminal uses a Nerd Font. Without one, they show as empty boxes. If your
  terminal has no Nerd Font, pass `--no-icons` to get a plain tree.
</Callout>

Press `?` at any time to see each keybinding and the legend for the marks in the tree and the gutter. You can also read the [keybindings reference](/docs/reference/keybindings).

## Configure it

stet runs without a configuration file. You do not have to write one by hand. Set up the app the way that you like it, then press `ctrl-s`.

![The status bar confirming ctrl-s saved the changed settings to the configuration file](/screenshots/save-settings.png)

`ctrl-s` saves your current session settings to `~/.config/stet/config.jsonc`. The saved settings are the theme, line wrap, the sidebar, and the search toggles. stet writes only the settings that differ from the file. Each write is a small edit that keeps your comments, and the status bar names what changed.

You can also edit the file yourself. The file has more settings than the keys can change:

```jsonc title="~/.config/stet/config.jsonc"
{
  "theme": { "dark": "catppuccin-mocha", "light": "catppuccin-latte" }, // follow the terminal
  "editor": "nvim +{line} {file}", // the e key
  "ide": "code {repo} --goto {file}:{line}", // the o key
  "keybindings": { "toggle-sidebar": "ctrl+e" },
}
```

The file holds themes, editors, keybindings, file associations, and icons. The [configuration reference](/docs/reference/configuration) describes each key.

## Upgrade

```sh
stet upgrade
```

`stet upgrade` updates stet to the latest release through the channel that installed it:

- A standalone install runs the install script again.
- An `npm` install runs `npm`.
- A Homebrew install runs `brew upgrade`.

First, the command reads the latest release from GitHub. If you already have that release, it prints `stet X.Y.Z is already up to date` and runs nothing.

While stet runs, it also looks for a newer release in the background. If one is available, stet prints a one-line notice when it exits normally. This background request does not block or interrupt the session.

## Requirements

- `git`
- A clipboard tool for copy (`y`): `pbcopy` on macOS (built in), or `wl-copy`, `xclip`, or `xsel` on Linux
- A Nerd Font for the file-type icons in the tree. This is optional. Without one, use `--no-icons`.
