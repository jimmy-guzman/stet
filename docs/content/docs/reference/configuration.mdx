A configuration file is optional. Without one, stet uses the `system` theme, which it builds from the colors of your terminal. If the terminal does not report its colors, stet uses `stet-dark` or `stet-light` to match its appearance. stet reads the editor commands from environment variables, and uses `vim` if no terminal editor is set.

## Location

stet reads its configuration once, at startup, from this file:

```
~/.config/stet/config.jsonc
```

If `$XDG_CONFIG_HOME` is set, stet uses it in place of `~/.config`. If `config.jsonc` does not exist, stet reads `config.json` in the same folder. It reads either file as JSONC, which is JSON with comments and trailing commas.

<Callout>
  A problem in the configuration never stops stet from starting. An invalid
  value affects only its own section, which falls back to its defaults. The rest
  of the configuration still applies. stet shows the problem in a notice. It
  also reports unknown keys, so a misspelled key does not fail silently. If the
  file is not valid JSONC, stet cannot read any of it. In that case, stet uses
  its built-in defaults and reports the parse error in the same way.
</Callout>

## Features

Each section of the configuration controls one feature, including the switch that turns it off. All settings are optional. This example shows each one with its default value:

```jsonc title="~/.config/stet/config.jsonc"
{
  "icons": { "enabled": true }, // Nerd Font file-type icons
  "viewer": { "wrap": false }, // wrap long lines instead of scrolling
  "sidebar": { "open": true, "changesOnly": false, "position": "left" }, // sizes default to the layout
  "update": { "check": true }, // background release check at launch
  "search": { "regex": false, "caseSensitive": false, "scope": "changed" },
}
```

| Key | Default | Effect |
| --- | --- | --- |
| `icons.enabled` | `true` | Nerd Font icons in the tree, pickers, and header (`--no-icons` forces off for a run) |
| `viewer.wrap` | `false` | wrap long lines in the viewer (`--wrap` starts a run wrapped, and `x` toggles from there) |
| `sidebar.open` | `true` | show the file tree at startup (`ctrl-b` toggles) |
| `sidebar.position` | `"left"` | the edge that the file tree docks to: `left`, `top`, `right`, or `bottom` (`d` cycles clockwise) |
| `sidebar.width` | responsive | tree width in cells while docked left or right, clamped to the terminal (`[` / `]` adjust, `\` resets) |
| `sidebar.height` | `10` | tree height in rows while docked top or bottom. Each axis keeps its own size |
| `sidebar.changesOnly` | `false` | the tree lists only changed files (`c` toggles) |
| `update.check` | `true` | look for a newer release on GitHub in the background at launch |
| `search.regex` | `false` | project search starts in regex mode (`ctrl-r` toggles) |
| `search.caseSensitive` | `false` | project search starts case-sensitive (`ctrl-x` toggles) |
| `search.scope` | `"changed"` | project search starts over changed files or the whole `"repo"` (`ctrl-g` toggles) |

A command-line flag overrides its configuration key for the run that you pass it on.

You set keyboard shortcuts in the same way. The `keybindings` section maps action ids to key combos (`{ "toggle-sidebar": "ctrl+e" }`). The value `false` removes the binding of an action. The [keybindings reference](/docs/reference/keybindings#custom-keybindings) lists the ids, the combo grammar, and the keys that you cannot change.

You do not have to edit the file by hand for these settings. Press `ctrl-s` in any view to save your current session settings to the configuration. The saved settings are the theme, icons, wrap, the sidebar, changes-only, and the search toggles. stet also saves any `--editor` or `--ide` flag that you passed for this run.

stet writes only the keys that differ from the file. Each write is a small edit that keeps your comments, and the notice names what changed. stet never writes an editor that it found in `$EDITOR` or a similar environment variable. It writes only a literal flag. If no configuration file exists, `ctrl-s` creates one.

## Editor and IDE

Set `editor` and `ide` to store command templates for two keys. The `e` key opens the terminal editor, and the `o` key opens a GUI editor or IDE. Both templates accept these placeholders:

- `{file}`, the file path
- `{line}`, the caret line. stet omits it when there is no caret line.
- `{repo}`, the repository root

`{repo}` is most useful in an `ide` template. When you pass the folder, the IDE opens the file in a workspace instead of a single-file window.

```jsonc title="~/.config/stet/config.jsonc"
{
  "editor": "nvim +{line} {file}",
  "ide": "code {repo} --goto {file}:{line}",
}
```

If the configuration has no value, each key uses a different fallback. The `editor` setting falls back to `STET_EDITOR`, then `$EDITOR` or `$VISUAL`, then `vim`. The `ide` setting falls back to `STET_IDE`, then to `$VISUAL` if it differs from `$EDITOR`. This follows the convention that `$VISUAL` names a GUI editor and `$EDITOR` names a terminal editor. If no IDE is set, `o` does nothing.

If a value is a bare editor name with no `{file}`, stet expands it to a known template. For example, `nvim` becomes `nvim +{line} {file}`, and `code` becomes `code {repo} --goto {file}:{line}`. stet knows these names: `code`, `cursor`, `emacs`, `helix`, `hx`, `idea`, `kak`, `micro`, `nano`, `nvim`, `subl`, `vi`, `vim`, and `zed`. The GUI editors in that list (`code`, `cursor`, `idea`, `zed`) get `{repo}` and open a workspace. The others get a terminal template with `{line}` and `{file}`.

stet adds `+{line} {file}` to a bare name that it does not know. It uses a value that contains `{file}` as a full template, without change. stet splits templates on whitespace, so it cannot run an editor from a path that contains spaces.

The `O` key opens the current file in the default app of your operating system. stet uses `open` on macOS and `xdg-open` on Linux. These commands use the system handler, so `O` needs no template or configuration.

## Themes

Set the `theme` key to a single theme name, or to a `{ "dark": ..., "light": ... }` pair. A pair follows the appearance of the terminal live. When you change the terminal between dark and light, stet changes its theme too.

Without `theme`, stet uses `system`. stet builds this theme from the background, the foreground, and the 16 colors of your terminal, so it matches the terminal. If the terminal does not report its palette, stet uses `stet-dark` or `stet-light` to match its appearance.

```jsonc title="~/.config/stet/config.jsonc"
{
  // follow the terminal, with a different theme on each side
  "theme": { "dark": "catppuccin-mocha", "light": "catppuccin-latte" },
}
```

The built-in themes are:

- `system`, from the palette of the terminal. stet lists it when the terminal reports a palette.
- `stet-dark` and `stet-light`, the themes of stet
- `opencode-dark` and `opencode-light`, based on the default theme of opencode
- `cmux-dark` and `cmux-light`, based on the default theme of cmux
- `mono-dark` and `mono-light`, where each color is a pure grey
- Each theme bundled with [highlights](https://diffs.com/highlights): editor themes such as `catppuccin-mocha`, `dracula`, `github-dark`, `gruvbox-dark-medium`, `nord`, `rose-pine`, and `tokyo-night`, and the `pierre-*` themes

A theme supplies only a palette. stet makes each UI color from that palette, as cmux does:

- Borders, text levels, and the cursor row are blends of the foreground into the background.
- The panel is the background, darkened toward black.
- Change kinds, stage colors, and severities use the terminal red, green, and yellow. Renames use magenta, and the untracked mark uses muted text.
- File icons use the terminal hue that suits each file type.
- The accent is the `text.accent` of the theme, or its magenta if it has no accent.

Code colors come from the `syntax` of the theme, so code and the UI always agree.

To add your own theme, put a [Zed theme](https://zed.dev/docs/extensions/themes) file in `~/.config/stet/themes/`. If `$XDG_CONFIG_HOME` is set, the folder is under it. stet lists each theme in the file by its name, in lowercase with dashes. For example, `My Ocean` becomes `my-ocean`. A theme with the name of a built-in theme replaces it.

stet reads these fields: `editor.background`, `editor.foreground`, `text.accent`, the six `terminal.ansi` hues (`red`, `green`, `yellow`, `blue`, `magenta`, `cyan`), and `syntax`. If a file is not a Zed theme, stet reports it in the status bar.

stet loads the files in name order. If two themes have the same name, stet keeps the first and reports the other in the status bar. stet also reports a theme whose name has no letters or digits, or a name that stet reserves:

- `system`, the palette of the terminal
- `auto`, the row in the switcher that follows the terminal
- `dark` and `light`, the old names of `stet-dark` and `stet-light`

```json title="~/.config/stet/themes/ocean.json"
{
  "name": "Ocean",
  "themes": [
    {
      "name": "My Ocean",
      "appearance": "dark",
      "style": {
        "editor.background": "#0b2433",
        "editor.foreground": "#d0e8f2",
        "text.accent": "#ffcc00",
        "terminal.ansi.red": "#ff6b6b",
        "terminal.ansi.green": "#7bd88f",
        "terminal.ansi.yellow": "#ffcc00",
        "terminal.ansi.blue": "#5ec4ff",
        "terminal.ansi.magenta": "#c792ea",
        "terminal.ansi.cyan": "#7fdbca",
        "syntax": {
          "keyword": { "color": "#c792ea" },
          "string": { "color": "#7bd88f" },
          "comment": { "color": "#577589", "font_style": "italic" }
        }
      }
    }
  ]
}
```

If `NO_COLOR` has a non-empty value ([no-color.org](https://no-color.org)), stet ignores the `theme` key and starts on the monochrome pair. Change marks still work without color. For example, the change bar of the diff shows `+` and `-` under any all-grey theme. A theme that you pick in the theme switcher still applies.

Press `t` in the app to open the theme switcher. You can try a theme there without editing the configuration. Type to filter by name. Move to a theme, or hover over it, to preview it on the whole UI. Press `enter` or click to apply it, or press `esc` to go back.

The change lasts for the session. To keep it, press `ctrl-s`. stet writes the previewed theme and any other changed settings to the configuration. If the file holds a `{ "dark": ..., "light": ... }` pair, stet changes only the half for the current appearance. If you save `auto`, stet removes the `theme` key.

## File support

A registry is a named list of entries. File support uses two registries on top of the built-in entries of stet. The `files` registry matches paths and selects a syntax and an icon for them. The `icons.glyphs` registry maps icon names to Nerd Font glyphs.

Each registry has its own entry shape, but both merge with the built-in entries in the same way:

- An object with an existing name keeps the fields that it does not set.
- An entry with a new name adds an entry.
- The value `false` removes an entry.
- An array replaces the array that it overrides.
- Icon entries are glyph strings, not objects.

A facet is one setting of a file association: its syntax or its icon. If an entry is invalid, stet shows a notice and keeps the built-in entry. If a file association names an unknown icon or syntax, stet drops only that facet.

This example highlights `.lua` files as Lua and gives them their own icon:

```jsonc title="~/.config/stet/config.jsonc"
{
  "icons": {
    "glyphs": { "lua": "\ue620" },
  },
  "files": {
    "lua": { "extensions": ["lua"], "syntax": "lua", "icon": "lua" },
  },
}
```

### Match files

A file association accepts `filenames`, `globs`, `extensions`, and `dotfiles`. Write extensions without a leading dot. A glob is a path pattern with wildcards. A glob that contains `/` matches the full POSIX path relative to the repository. Any other glob matches only the file name. Matching ignores case, unless `caseSensitive` is `true`.

Each association can set `syntax` and `icon`. Built-in and user associations share one order of precedence. stet resolves each facet on its own, from the most specific match to the least: exact filename, glob, extension, then dotfile. At the same level, the later association wins. stet registers user entries after built-in entries. If you set a facet to `false`, less specific matches for that facet stop. The syntax becomes plain text, or the icon becomes the generic file glyph.

```jsonc title="~/.config/stet/config.jsonc"
{
  "files": {
    "generated": {
      "globs": ["generated/**/*.ts"],
      "syntax": "typescript",
      "icon": false,
    },
    "docker-compose": {
      "filenames": ["compose.yaml", "compose.yml"],
      "syntax": "yaml",
      "icon": "docker",
    },
  },
}
```

If no association sets a syntax, stet uses its bundled file-name inference to find a language. A bare dotfile name does not count as an extension.

If no association sets an icon, stet uses the `complete` icon set of Trees to match file names and extensions. It then maps the result to a Nerd Font glyph. Unknown file types use `file`. To override a default of Trees, add a `files` entry with explicit match rules. The default icon rules are no longer named `icon-*` entries in the `files` registry.

<Callout>
  If an entry is not valid, stet reports it in a notice, and the rest of the
  configuration still applies. An invalid override of a whole entry keeps its
  built-in entry. An invalid reference in a file association drops only the
  facet that it affects.
</Callout>

## Environment variables

| Variable | Effect |
| --- | --- |
| `STET_EDITOR` | fallback command template for the `e` key |
| `STET_IDE` | fallback command template for the `o` key |
| `EDITOR` / `VISUAL` | read after the `STET_*` variables. The two keys read them differently. See [Editor and IDE](#editor-and-ide) |
| `NO_COLOR` | any non-empty value starts stet on the monochrome `mono-dark` / `mono-light` themes instead of the configured one |
| `FORCE_COLOR` | overrides `NO_COLOR`. `0` or `false` forces monochrome, and any other value keeps the configured theme |
| `XDG_CONFIG_HOME` | base folder for the configuration file |
