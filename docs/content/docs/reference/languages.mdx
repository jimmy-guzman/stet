Language support has layers. Named file associations select the syntax and the icon of a file separately. The coverage of highlighting, folding, and icons depends on the library for each one. You can change each layer in [your configuration](/docs/reference/configuration#file-support).

Press `z` to fold the block at the caret (the current position in the viewer). Code folds by indentation in each language, and Markdown folds by heading section. [Reading files and diffs](/docs/guides/reading-files-and-diffs#fold-code) describes folding.

## Syntax highlighting

stet highlights code with [`@pierre/highlights`](https://diffs.com/highlights), which bundles lexers for about 190 languages. A lexer splits the code of one language into tokens for color. stet selects the language from the file name, including exact names such as `Dockerfile`. The diff, the full-file view, and the search results use the same highlighter and theme. A file type that stet does not know shows as plain text.

A dotfile is a file whose name starts with a dot. Configuration dotfiles have no extension to select a language from, so stet resolves them by name. `.npmrc` highlights as INI, and `.prettierrc` highlights as JSONC, so a comment in it shows as a comment. Their extension variants, such as `.prettierrc.json` and `.prettierrc.yaml`, already resolve by their extension.

## File icons

Known file types use colored Nerd Font icons. Structural and generic icons stay muted. Well-known brands keep their own look, and formats without a brand use the palette of stet. A file shows the same named icon and theme color in each file list.

The default file matching comes from the `complete` icon set of Trees, which stet maps to terminal glyphs and colors. stet overrides Trees for some names. Test files (`*.test.*`, `*.spec.*`, `*_test.*`, `*_spec.*`, `test_*.*`, `*.cy.*`) use the test icon, and stories use the Storybook icon. `package.json`, `tsconfig.json`, `README`, `LICENSE`, `Makefile`, `go.mod`, and the Gradle and Maven build files each have their own icon, and so does `.csv`, which Trees shows as a table. Ruby templates (`*.rb.tmpl`), which Trees does not recognize, use the Ruby icon. A README or LICENSE gets its own icon only as a document, so `License.tsx` keeps the React icon. Where Trees has no icon, stet gives Java, Kotlin, Scala, Groovy, TOML, `.lock` files, PDFs, videos, HTTP request files, CPU profiles, and Mako templates their own icon, and any other dotfile uses the config icon. User associations override these defaults. If your terminal font has no Nerd Font glyphs, `--no-icons` hides them and keeps the layout stable.

To add a file type, map it to a syntax and an icon with a `files` association. [Configuration](/docs/reference/configuration#file-support) describes the matching rules and how to override or disable a built-in entry.
