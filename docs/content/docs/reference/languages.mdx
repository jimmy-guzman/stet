Language support is layered. Named file associations select syntax and icons independently. Highlighting, folding, and icon coverage depend on their respective libraries. You can change any layer through [your config](/docs/reference/configuration#file-support).

## Syntax highlighting

stet highlights with [`@pierre/highlights`](https://diffs.com/highlights), which bundles lexers for more than 150 languages. stet picks the language from the file's name, including exact names such as `Dockerfile`. The diff, full-file view, and search results share the same highlighter and theme. An unrecognized file type falls back to plain text.

Config dotfiles carry no extension to pick a language from, so they resolve by name: `.npmrc` highlights as INI and `.prettierrc` as JSONC, so a comment in it reads as a comment. Their extension variants, such as `.prettierrc.json` and `.prettierrc.yaml`, already resolve on the extension.

## Folding

Press `z` to fold the block at the caret: code folds by indentation in every language, markdown folds by heading section. See [reading files and diffs](/docs/guides/reading-files-and-diffs#fold-code).

## File icons

Recognized file types use restrained colored Nerd Font icons; structural and generic icons remain muted. Recognizable brands keep their identity, while unbranded formats reuse stet's palette. The same named icon and theme color appears in every file-list surface. Default file matching comes from Trees' `complete` icon set, with its categories mapped to terminal glyphs and colors. For example, `package.json` uses the JSON icon and test files retain their language icon. User associations override these defaults. `--no-icons` hides glyphs while keeping the layout stable if your terminal font lacks them.

To add a file type, map it to a syntax and an icon with a `files` association. See [configuration](/docs/reference/configuration#file-support) for matching rules and overriding or disabling built-ins.
